# 数据存储结构

运行期数据分成两部分：SQLite 保存结构化数据（书源、书架、进度、书签、AI 记忆等）以及**全部章节正文与版本历史**；文件系统保存图片与上传资源这类大块内容。这篇讲文件部分怎么组织、文件名怎么来、什么时候会被清理。表结构见[数据库](/maintainers/database)。

位置由三个配置决定：

| 配置           | 默认值                              | 作用                                                     |
| -------------- | ----------------------------------- | -------------------------------------------------------- |
| `STORAGE_DIR`  | `storage`                           | 运行期数据根目录                                         |
| `DATABASE_URL` | `sqlite:storage/reader.db?mode=rwc` | SQLite 文件位置，可以指到 `storage/` 之外                |
| `ASSETS_DIR`   | `storage/assets`                    | 上传资源目录，对外挂在 `/assets` 下，也可以独立配置      |

`storage/`、`.env`、`DATABASE_URL` 都按进程的工作目录解析，所以要在仓库根目录（或部署目录）启动。首次启动会自动创建目录、建库并执行迁移。

## 目录总览

```text
storage/
├─ reader.db                       SQLite 主库（WAL 模式，另有 reader.db-wal / reader.db-shm）
├─ jwt_secret                     JWT_SECRET 留空时自动生成；多实例部署要显式共享同一个值
├─ logs/
│  └─ reader-rust.log.YYYY-MM-DD  按天滚动，stdout 同内容另有一份
├─ cache/                         可再生数据：删掉只会让下次访问重新抓取
│  ├─ <ns>/
│  │  ├─ toc/book_<n>.json                           目录（1 小时 TTL）
│  │  ├─ source_candidates/book_<n>.json             换源候选
│  │  └─ cover/                                      旧版封面目录，只统计与清理历史文件
│  ├─ bookinfo/<ns>/book_<n>.json                    书籍详情（1 小时 TTL）
│  ├─ reviews/<ns>/book_<n>/<md5(缓存键)>.json       章评/段评（7 天 TTL）
│  ├─ image/<id>.bin、<id>.json                      书源图片，全局共享
│  └─ invalid_book_sources/<ns>.json                 失效书源清单
├─ data/                          用户资产：不能从上游重新生成
│  └─ <ns>/
│     └─ local_books/<hash>/                         本地 TXT / EPUB
├─ assets/                        上传资源（ASSETS_DIR）
│  └─ <ns>/<类型>/<文件名>
└─ webdav/<ns>/                   WebDAV 文件
```

`<ns>` 是用户命名空间，恒为 `user_<uid>`；`<n>` 是书籍登记表的自增 id。单用户部署下只有一个命名空间，目录层级仍然保留。

## 命名约定

### 用户命名空间

`user_ns` 是数据隔离键，等于 `user_<uid>`（`uid` 来自 `users` 表）。数据库里的 `user_ns` 列、缓存目录、`data/`、`assets/`、WebDAV 目录都按它分目录，handler 不需要感知当前用户名。改用户名不会搬动任何文件。

### 书籍 id

书籍对外一律是 `book_<n>` 文本，例如 `book_12`。写进文件路径前会先归一：`book_007`、`book_+7` 都变成 `book_7`，同一本书不会出现两份缓存；非法 id（含 `../`、绝对路径等）归入 `__invalid_book__` 隔离段，读为空、删除是空操作。这道校验在 repo、service、文件缓存三层都有，handler 层的 `resolve_book` 是主防线。

### 内容摘要

| 位置             | 摘要对象                       | 用途                                                         |
| ---------------- | ------------------------------ | ------------------------------------------------------------ |
| 正文池           | 原文 SHA-256                   | `chapter_contents.content_hash`，相同正文只存一份            |
| 评论缓存         | 缓存键（章节、页码、排序、版本等） | `md5` 命名；键的构成见「评论缓存」一节                       |
| 图片             | 去掉查询串的上游地址           | `md5` 生成 id，同时是 `/reader3/image/<id>` 的路径参数       |
| 本地 TXT / EPUB  | 用户命名空间、文件名与内容摘要 | 作为 `local-txt:` / `local-epub:` 伪书源地址的后半段         |

摘要只用于生成稳定的键/文件名，不承担安全校验。

## cache/：可再生数据

`cache/` 下的内容都能从上游或用户数据重新生成，整个目录可以直接删。除章节列表、书籍详情与评论外，其余缓存不按时间过期，只在显式清理或超出容量时回收。

**章节正文不在 `cache/` 下**：它存在 SQLite 的 `chapter_contents` / `chapter_versions` 里，包含上游历史与用户版本，严格保留、不自动淘汰。正文可能是纯文本或 HTML；HTML 内嵌的 `<img>` 由浏览器直接按上游地址加载，独立配图接口的图片地址带时效签名，都不写入正文池。

### 目录与书籍详情

- 目录：`cache/<ns>/toc/book_<n>.json`，1 小时 TTL。
- 书籍详情：`cache/bookinfo/<ns>/book_<n>.json`，1 小时 TTL。详情过期会在读取时删除；目录过期只在「直接返回响应」的路径按未命中处理，文件保留给内部只读路径，等重抓后覆盖。
- 两者都归 `CacheKind::ChapterList` 清理（详情与目录同属书籍元数据）。

### 换源候选

路径：`cache/<ns>/source_candidates/book_<n>.json`，保存这本书在各书源中的搜索结果，供换源面板使用。

它按 1 小时 TTL 过期（按文件 mtime 判断）：换源面板与 SSE 候选推送直接读取这份缓存，超过 1 小时后按未命中处理并重新搜索；换源改绑时回填元数据也使用未过期的候选。过期文件不会删除，直接读取仍能拿到内容。换源成功时只清目录、详情与评论，保留这份候选清单，下一次换源仍然可用；正文历史也不会因为换源删除。按书清理或按用户清理时才删除候选清单。

### 评论缓存

路径：`cache/reviews/<ns>/book_<n>/<md5(缓存键)>.json`。

- 缓存键包含章节 URL、页码、每页条数、排序（`hot` / `time`）与正文版本（`edited` / `upstream`），因此切换排序或正文版本不会复用对方的条目。
- 默认 7 天 TTL（`REVIEW_CACHE_TTL_SECS`，`0` 表示不过期）。评论会变，新评论、点赞数和热度排序每天都在动，所以它保留时间过期，而正文历史严格保留。
- 容量上限 `REVIEW_CACHE_USER_LIMIT_BYTES` 默认 64 MiB，按用户计量，同样按最旧优先淘汰。
- 空页不写盘：上游限流、超时与「确实没有评论」在响应上难以区分，缓存空页会把一次抖动放大成一周的空列表。

### 图片缓存

路径：`cache/image/<id>.bin` 与 `<id>.json`，其中 `id = md5(去掉查询串的地址)`。

- `<id>.bin` 是图片本体；`<id>.json` 是映射记录，包含上游地址、用途（封面 / 章节配图 / 评论配图）、内容类型、所属 `book_id` 与最近一次失败时间。
- 目录全局共享，不在任何用户命名空间下：图片 id 由地址决定，封面本身也是匿名资源。
- 不设 TTL。容量上限由 `CACHE_COVER_LIMIT_BYTES` 控制，默认 256 MiB，封面、章节配图与评论配图共用这个上限，超出后按修改时间最旧优先删除。
- HEIC 图片会在写入磁盘前转成 JPEG，记录里的内容类型与扩展名随之更新。
- 上游地址失效时，按记录里的 `book_id` 找到当前绑定的书源重新抓取一次；仍失败才返回错误。
- 按书清理缓存时，扫描记录里的 `book_id`，删掉这本书登记过的图片；按用户或全部清理时，整个 `cache/image` 目录一起删除。
- 旧版本的封面目录 `cache/<ns>/cover/` 仍在统计与清理范围内，但当前封面已经统一走图片管道，不再写入。

### 失效书源清单

路径：`cache/invalid_book_sources/<ns>.json`，记录批量检测中判定不可用的书源。没有 TTL，随按用户清理或全部清理删除。

## data/：用户资产

`data/` 保存无法从上游重新生成的内容。删掉它等于丢失用户输入，备份时必须带上。章节编辑版与手动导入版本不在 `data/`：它们作为用户版本进入正文池，随 `reader.db` 一起备份。

### 本地 TXT

路径：`data/<ns>/local_books/<hash>/`。

- `book.txt`：上传的原始文本，读取时整本缓存进内存。
- `chapters.json`：章节索引，记录每章的标题、序号与在文本中的字节区间。翻章按区间切片，不需要每次重新分词。
- 上传上限 50 MB；整本正文与章节索引各有进程内缓存，重启后重新读取。
- `<hash>` 由用户命名空间、文件名与正文摘要共同决定，重复导入同一本书会覆盖同一个目录。

### 本地 EPUB

路径同样是 `data/<ns>/local_books/<hash>/`，内容结构不同：

```text
<hash>/
├─ original.epub      原始文件
├─ manifest.json      章节与资源清单
├─ chapters/          按 spine 顺序清洗后的章节 HTML
└─ assets/            按书内原路径展开的图片等资源
```

上传上限 80 MB，解压后的总大小上限 300 MB。重复导入会删除旧目录后重建。

### 旧版 userConfig.json

`data/<ns>/userConfig.json` 是旧版本的用户配置快照。当前配置保存在 `json_documents` 表（文档名 `userConfig`），读取时如果表里没有，会把旧文件读进表然后删除文件。新部署不会再生成这个文件。

## assets/：上传资源

路径：`assets/<ns>/<类型>/<文件名>`，对外地址是 `/assets/<ns>/<类型>/<文件名>`。

- 类型来自 `uploadFile` 的 `fileType` 参数，默认 `images`，只允许字母、数字、下划线与连字符。
- 单文件上限 32 MB；文件名经过白名单校验，拒绝路径分隔符、`..` 与 Windows 保留设备名。
- AI 资料生成的地图图片写入 `assets/<ns>/ai-maps/`，文件名由时间戳与内容摘要组成。
- 这些文件不会自动过期，也不会随删书自动删除。自定义封面等引用关系由前端维护，删除文件走 `deleteFile` 或手工清理。
- 静态路由先查前端构建产物 `WEB_ROOT/assets`，未命中再查 `ASSETS_DIR`，两处目录不会混淆。

## webdav/

路径：`storage/webdav/<ns>/`。WebDAV 协议端点使用 HTTP Basic 认证，目录按用户命名空间隔离；相对路径会同时按 `/` 与 `\` 切分，并拒绝 `..`、盘符、NTFS 数据流与设备名，避免 Windows 上越出根目录。

## 日志与密钥

- `storage/logs/reader-rust.log.YYYY-MM-DD`：按天滚动，文件里不带终端颜色码；Python sidecar 的 stderr 经主进程日志转发，也写进同一个文件。
- `storage/jwt_secret`：`JWT_SECRET` 未配置时生成 48 个字符的随机串并保存在这里，文件权限收紧为仅属主可读写（Unix）。多实例部署必须显式配置同一个 `JWT_SECRET`，否则各实例签发的令牌互不认可。删除该文件会让已有登录态全部失效。

## 进程内缓存

下面这些状态只存在于内存里，重启即失效，不进入备份：

| 缓存                     | 键与上限                                                          |
| ------------------------ | ----------------------------------------------------------------- |
| 书源正则编译结果         | 按规则文本缓存，条目数有上限                                      |
| 书源 JS 的 `cache` / `kv` | 键带用户前缀；条目数上限与总字节上限，超出后整表清空              |
| jsLib 编译结果           | 条目数有上限，1 小时 TTL，远程脚本更新后不会永久使用旧版本        |
| `exploreUrl` 求值结果    | 键包含用户命名空间、书源地址与脚本；1 小时 TTL，条目数有上限      |
| 本地书的正文与章节索引   | 按用户与书缓存，文件修改时间变化后重新读取                        |
| WebDAV 凭据校验结果      | 5 分钟 TTL，条目数有上限，避免每个请求都跑一次 Argon2             |

## 清理与回收

| 操作                                | 影响                                                                                                                                                                                       |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 删除书籍                            | 只删书架行、书签、AI 记忆、目录/详情/换源候选/评论缓存、本地书文件与按 `book_id` 登记的图片记录。**书籍登记行、正文池与版本历史保留**，重新加入同一地址会接回原 bookId |
| `purgeCache`，`scope=book`          | 该书的目录、详情、换源候选、评论与图片；不动书签、本地书文件与正文历史                                                                                                                     |
| `purgeCache`，`scope=user`          | 该命名空间下的目录、换源候选、评论、旧封面与失效书源清单，以及全局图片目录；不删除书籍登记行，也不动正文历史。书籍详情缓存不在此列，它按 1 小时 TTL 自行失效，也可以用 `scope=kind&kind=chapterList` 或 `scope=book` 清掉 |
| `purgeCache`，`scope=kind`          | 只清指定的一层：封面、目录、换源候选或评论（没有正文）                                                                                                                                     |
| `purgeCache`，`scope=all`           | 对每个命名空间执行 `scope=user`，再清评论缓存与残留空目录；正文历史保留                                                                                                                    |
| 容量淘汰                            | 评论与图片超过各自上限时，按修改时间最旧优先删除；正文历史没有容量淘汰                                                                                                                     |
| TTL                                 | 目录与详情 1 小时；评论 7 天（可配置为不过期）；图片不过期；正文按 `CONTENT_REVALIDATE_TTL_SECS` 回源，但版本不删                                                                           |

目标用户与清理范围由 `/reader3/purgeCache` 控制，逐层占用可以用 `/reader3/cacheStats` 查看，详见[缓存管理 API](/api/cache)。

## 备份与迁移

需要备份的内容：

- `reader.db`，以及同目录下的 `reader.db-wal`、`reader.db-shm`。**正文池、上游版本历史、编辑版和手动导入版本都在这个库里**，备份它才能保住这些内容。运行中复制 SQLite 文件可能拿到不一致的状态，稳妥做法是停服后复制，或使用 SQLite 的在线备份接口。
- `data/`：本地书文件。
- `assets/`：上传资源与 AI 地图。
- `webdav/`：WebDAV 里保存的文件。
- `jwt_secret`：需要保留登录态时一起备份；不备份则升级后所有令牌失效，重新登录即可。

`cache/` 可以跳过，恢复后会按需重新抓取；`logs/` 只用于排查问题。`DATABASE_URL` 指向 `storage/` 之外时，记得单独备份那个位置。

遇到正文池相关的破坏性结构升级（当前 beta 之前），官方做法是停止服务、删除 `storage/` 后重新启动，再重新导入书源与书架。具体版本说明见[快速开始](/guide/quickstart)。

## 设计取舍

- **正文也进数据库**：正文池、版本时间线和最新指针三张表让上游历史与用户版本都不再被覆盖，正文按 SHA-256 去重并用 zstd 压缩。代价是 `reader.db` 会随历史增长，而且正文历史不提供清理入口；备份必须包含这个库。
- **`cache/` 与 `data/` 严格分开**：前者可以随时删除，后者不能。默认清理、容量淘汰与备份都以这条边界为依据；正文历史既不在 `cache/` 的可清理范围，也不依赖 `data/` 的文件。
- **图片单独一个全局目录**：图片 id 由地址决定，同一张封面可能被多本书引用；集中存放便于去重、转码与按 `book_id` 清理。代价是按用户清理时会删掉所有用户的图片，单用户部署下没有实际影响。
- **正文版本不设 TTL，评论缓存设 TTL**：正文版本是历史，删掉就找不回来；评论是会变的第三方数据，保留时间过期。正文只在读取时按 24 小时回源检查，回源失败继续用缓存。
