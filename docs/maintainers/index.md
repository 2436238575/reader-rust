# 维护者文档

本目录面向**仓库维护者**，讲的是源码怎么组织、版本怎么发、改动有什么约定。使用与部署请看 [指南](/guide/)。

| 文档 | 内容 |
|------|------|
| [架构说明](./architecture) | 分层结构、模块职责、请求链路、解析引擎、存储设计、扩展点 |
| [发布流程](./release) | `scripts/release.sh` 的完整行为、镜像标签规则、失败处理 |
| [开发约定](./development) | 代码约定、测试要求、文档维护规则、提交与分支 |

## 先读这个

改动前请先读仓库根目录的 `AGENTS.md`（**不在本文档站内**）—— 它是工程事实的唯一权威：命令、配置默认值、代码结构、测试规模、开发约定。本目录的文档是它的展开说明，两者不一致时以 `AGENTS.md` 与代码为准。

## 一条贯穿全仓的规则

**文档是开发目标的一部分。** 若某功能只在文档中描述、代码尚未实现，**不要删除文档条目**，按统一格式标注状态后保留：

```text
> **未实现**：<说明>（依据：<代码位置>）
```

这样后来者能区分「没做」与「做过后移除了」。历史设计与计划快照统一归档在 [`docs/archive/`](/archive/)，同样只标注、不删除。
